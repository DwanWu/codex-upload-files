# Egern 小组件维护说明

- 智能热搜：AIHOT 官方新域名 aihot.news；ETag 条件请求，429/503 尊重 Retry-After，去重及链接白名单，最多6小时客户端缓存并标示时间。不对外镜像数据。官方文档：https://aihot.news/agent?tab=api
- 黄历查询：双源兼容完整日期与带年月标题的两位日期；按月保存校验过的日期记录，24小时内复用，故障30分钟退避。北京时间午夜切换，不复用其他日期宜忌。本地 Intl 农历核对；宜忌属传统历法参考，不保证双源完全一致。
- 节点体检：先通过 IPPure（失败则 IPQuery）获取检测请求的公网出口，再用 Proxycheck v3 与 IPQuery 的指定地址接口查询同一个 IP。纯度是 `100 − max(有效 Proxycheck 风险值, 有效 IPPure 风险值)`，属于本组件的保守参考换算，没有统一的官方纯净度标准。原始值为 0 时正常显示 100；缺失、错误、超限和不支持的评分不会被当成 0。不同 IP 可以合法得到相同分数，不能为了让分数变化而编造扣分。主评分卡不显示 Proxycheck参考字样，内部保留原始分数和来源。
- 原订阅 URL 不变，脚本内部版本更新。WidgetKit 可能延迟刷新。回归命令：node scripts/test_egern_widgets.mjs。测试使用模拟网络和固定时间；真机需验证。

## 节点体检评分依据与故障处理

- [Proxycheck v3 文档](https://proxycheck.io/api/)：使用 `detections.risk` 的有效数值；`0` 与其他合法分数同等处理，不要求备用接口同时成功。`last_updated` 是数据库元数据时间，不按“超过24小时”否决零风险；HTTP `Age` 超过15分钟的响应仍拒绝。`detection_history.delisted` 是历史信息，可以与后来的 VPN 等当前检出并存，不据此丢弃当前评分。可选检测字段的 `null` 或缺失保留为未知，不能当成 false。分数越界、类型错误、目标 IP 不匹配和明确无效时间仍拒绝。
- [IPPure 接口](https://ippure.com/MyIP-Info-API)及[FAQ](https://ippure.com/faq)：只使用同一 IPv4 的有效 `fraudScore`，IPv6 不使用此评分。公开 API 仍标注测试阶段；没有单个 IP 记录时可能依据地址段推断。IPv6 可以使用有效 Proxycheck 评分，包括合法零值；不支持评分不等于零风险。
- [IPQuery 接口](https://ipquery.io/developers/api)及[风险分说明](https://ipquery.io/glossary/risk-score)：用于同地址风险/属性辅助数据和出口识别，其风险值不用于纯度换算。该分数不是概率，机房和移动网络本身不增加分值。只有风险值和检测字段足够时才参与低风险判断。
- 风险高/中/低是组件根据原始分数和检出标记作出的参考分类。单个有效低风险来源可正常显示“低”，备用接口不可用不会自动把它改为“未知”；有明确风险证据时优先显示高/中。来源评分相差至少30分，或属性、检测标记有冲突时保留差异提示。30分只是提示阈值，并非科学校准。有效零风险换算出的100不代表绝对安全，也不保证目标网站放行。
- 只要有效评分中有非零风险，保留较高的那个；显示精度不会把非零风险四舍五入成100。两家评分都不可用时显示 `-- / 评分暂缺`，不填固定分。所有查询绑定本次测得的同一 IP，不保存或复用上个节点的 IP、评分。
- 匿名 Proxycheck 额度100次/日，可能拒绝代理来源；注册免费额度1000次/日。可以在本机模块设置填自己的密钥。设备侧分别限制80/800次/UTC日，并对拒绝、限流退避；仅保存计数和时间戳。正常约30分钟刷新，数据不足15分钟；服务端匿名 CDN 缓存可能约10分钟，实际组件刷新由 WidgetKit 控制。
- 单次请求最多8秒，模块总执行上限30秒，为最多三段串行请求保留余量。实际联调中4秒会截断有效响应，因此本版同时调整脚本与模块的超时；不能只更新 JS 而保留旧15秒模块配置。

## 检测哪个节点

在 Egern 的“节点体检”模块设置中，填写“检测策略”（环境变量 `NODE_POLICY`），值为你实际使用的**节点或策略组完整名称**。例如，若真实策略组名为“香港节点”，就填“香港节点”；不要照抄一个不存在的名称。留空不会指定请求策略，也无法保证查询随你切换的代理节点改变。原有手工设置的同名环境变量继续生效。

所有出口探测及后续查询都传入该策略；指定策略失败时不会偷偷改成 DIRECT。Egern 官方文档支持 [HTTP policy 参数](https://egernapp.com/zh-CN/docs/javascript-api/)和[模块 env_schema 设置项](https://egernapp.com/zh-CN/docs/configuration/modules/)，但没有公开自动读取当前选中节点的接口。不同网站的规则、负载均衡策略可能使用不同出口，因此这里测量的是该次检测连接的出口，不保证所有网站都走同一个地址。

如果切节点后分数不变，先看组件底部“出口 IP”：相同分数可能正确，检测 IP 是否跟随目标节点变化才是路由检查的依据。更新模块后刷新脚本；脚本 URL 的版本参数用于区分本次修复版本。
